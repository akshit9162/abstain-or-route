Route the request, or know when to hand it to a human.

Intent routing for support requests in 10 languages with a multilingual Transformer and LoRA written from scratch in PyTorch. Three questions: how close LoRA gets to full fine-tuning, what English-only training costs in other languages, and whether the model's confidence is good enough to decide when to defer.

The problem

Every request gets routed, or handed off

A support system receives "my alarm didn't go off", "wecke mich um sieben" and "मेरा अलार्म सेट करो", and each must reach the right intent. Labelled data is mostly English, and a wrong route costs more than a slow one, so the model also has to know when it doesn't know.

Data: MASSIVE 1.1

Amazon Science, CC BY 4.0. Parallel across languages: test utterance k is the same request everywhere, so language gaps are paired.

Equal data budgets

English-only uses all 11,514 English utterances. Multilingual uses 11,510, split evenly over 10 languages and drawn from disjoint utterance ids.

No peeking

Model selection and temperature use only the training languages' dev split. Zero-shot languages are first seen at test.

Parameter-efficient fine-tuning

LoRA, written out

A frozen weight W gets a trainable low-rank update: W x + (α/r)·B A x, with B initialised to zero so training starts exactly at the pretrained model. Wrapped layers: attention query and value, rank 8, α = 16.

class LoRALinear(nn.Module):
    def __init__(self, base, r, alpha, dropout=0.1):
        ...
        self.A = nn.Parameter(torch.empty(r, base.in_features))
        self.B = nn.Parameter(torch.zeros(base.out_features, r))   # starts at the pretrained model
        self.scale = alpha / r

    def forward(self, x):
        return self.base(x) + (self.drop(x) @ self.A.T @ self.B.T) * self.scale

Full fine-tuning freezes the 250k-token embedding table: 96M of the 118M parameters. Its optimizer state pushed an 8 GB machine into swap, and a batch touches only a few hundred of its rows.

12 pytest tests check that LoRA starts exactly at the pretrained model, trains only A and B, and applies the α/r scale; plus the calibration, abstention and data-split code.

A threshold can't rescue a language the model doesn't know. The temperature is fitted on English, which is all an English-only system has; it barely moves the fine-tuned models and can't fix Swahili or Tamil, where the model is confidently wrong. Deferring 20% buys Hindi 10 points and Swahili 4. Multilingual training makes confidence reliable everywhere.
What this doesn't show

Limitations

One seed per run

CIs cover test-set sampling, not training variance. The English LoRA-vs-full tie is the most seed-sensitive claim.

Embeddings frozen in full fine-tuning

Updating them might widen full fine-tuning's multilingual lead.

One LoRA configuration

Rank 8 on query/value only. A rank sweep is the natural next test for the multilingual gap.

Swahili's cause is untested

How much Swahili the encoder saw in pretraining isn't checked here.
